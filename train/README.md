# Обучение ядра LLM

Цель: получить модель, которая по доходностям последних свечей даёт направление
следующего бара, и включить её в ядро **только** если она статистически обыгрывает
точку безубыточности и простые базовые линии на отложенных данных.

Точка безубыточности при выплате 80%: 1/(1+0.80) = **55.56%**. Ниже этой доли
бинарные опционы дают убыток независимо от «красивых» метрик.

## Шаг 1. Загрузка истории

Сначала проверка формата запроса (один запрос, без записи файлов):

```
node tools/history_download.js --probe
```

Если ответ получен, загрузка года по пяти OTC-парам (по умолчанию из `config/history.json`):

```
node tools/history_download.js                 # 365 дней, 1 мин, -> data/otc/hist_*.csv
node tools/history_download.js --days 30       # короткий тест
```

Проверка скачанного файла перед обучением:

```
python3 tools/check_history.py data/otc/hist_EUR_USD_OTC_1m.csv
```

Прерывание (Ctrl+C) сохраняет прогресс, повтор команды докачивает дальше назад.
Оценка времени: 525 600 минут на пару, около 200 свечей за запрос, около 2 600 запросов
на пару. При паузе 500 мс это порядка часа на пару.

Формат запроса `loadHistoryPeriod` в `config/history.json` **не подтверждён** захватом
реального трафика. Если `--probe` не получает ответ, сверьте имя события и поля
в браузере (DevTools -> WS) и поправьте конфиг, код менять не нужно.

Ранее использованный сбор «вживую» (`tools/collect_candles.js`) остаётся для
непрерывного накопления свежих данных. Исторический загрузчик нужен для одноразовой выгрузки года.

Сегменты (`config/segments.json`) собираются и обучаются **раздельно**. Смешивать обычные пары и OTC в одном датасете нельзя.

Брокер отдаёт до ~200 свечей за запрос и не даёт пагинацию, поэтому датасет
копится непрерывной работой. Ориентир: **не меньше 50 000 закрытых баров**
(≈ 5–6 недель непрерывной работы на 1-минутках). Файл дописывается, дубликаты
по времени пропускаются.

Не обучайте на собственных решениях бота из `data/llm_decisions.jsonl`: это
выборка, отобранная самим ботом, и она смещена.

## Шаг 2. Сборка датасета без утечек

```
python3 train/build_dataset.py data/otc/hist_EUR_USD_OTC_1m.csv --pair "EUR/USD OTC" --segment otc --period 60
# результат: train/data/otc/{train,val,test}.jsonl
```

* хронологические сплиты 70 / 15 / 15, без перемешивания;
* окно признаков и бар метки целиком внутри одного сплита (пограничные примеры отбрасываются);
* разрывы во времени и ничьи отбрасываются.

## Шаг 3. Базовые линии

```
python3 train/evaluate.py --segment otc --baselines-only
```

Если логистическая регрессия на 20 доходностях и правила «momentum/reversal» не
отличаются от 50%, модель вряд ли найдёт то, что не нашли они. Это первый честный
тест, и его нужно пройти до дообучения.

## Шаг 4. Дообучение LoRA

```
pip install torch "transformers>=4.44" "peft>=0.12" "datasets>=2.20" accelerate
python3 train/finetune_lora.py --segment otc    # -> train/out/otc/lora
```

**Скрипт не проверен на реальном железе.** При первом запуске сверьте версии
и смотрите на предупреждения. Потери считаются только по ответу модели.

## Шаг 5. Слияние и квантование в GGUF Q4_K_M

Нужен llama.cpp (скрипты конвертации и `llama-quantize`):

```
# 1) слить адаптер с базой (короткий скрипт: AutoModel... -> PeftModel.from_pretrained(...).merge_and_unload().save_pretrained("train/out/merged"))
python3 llama.cpp/convert_hf_to_gguf.py train/out/merged --outfile train/out/model-f16.gguf --outtype f16
llama.cpp/llama-quantize train/out/model-f16.gguf train/out/qwen2.5-3b-instruct-q4_k_m.gguf Q4_K_M
```

Проверьте, что файл открывается в GPT4All (та же версия llama.cpp, что в вашей сборке).

## Шаг 6. Оценка

Чекпойнт выбирается по **val**, тест используется **один раз**:

```
python3 train/evaluate.py --segment otc --split val  --backend gpt4all --model-dir train/out/otc --model-file otc-qwen2.5-3b-q4_k_m.gguf
python3 train/evaluate.py --segment otc --split test --backend gpt4all --model-dir train/out/otc --model-file otc-qwen2.5-3b-q4_k_m.gguf
```

## Критерий допуска в ядро

Все условия обязательны (вывод `evaluate.py` на test):

1. сделок на тесте ≥ 1000;
2. нижняя граница 95% Wilson для точности **> 55.56%**;
3. точность **> лучшей базовой линии** на тесте;
4. итоговый эксперимент на test проводился один раз.

Только после этого:

```
# в .env для этого сегмента:
LLM_URL_OTC=http://127.0.0.1:8788/decide   # сервис: LLM_SEGMENT=otc LLM_MODEL_FILE=otc-qwen2.5-3b-q4_k_m.gguf
# сегмент без допущенной модели не включаем: его LLM_URL_* не задаём -> NONE
```

Если критерий не пройден для сегмента, его сервис не запускаем: сделок по этому сегменту не будет. Новые данные переобучения собираются из `tools/collect_candles.js`,
а не из собственных решений бота.
